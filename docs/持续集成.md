# 持续集成

## 支持边界

| 平台 | CI 范围 | 产品承诺 |
|---|---|---|
| macOS | 隔离浏览器、完整合成测试、Lint、凭据扫描和构建 | 正式支持方向 |
| Linux | 隔离 Chromium、完整合成测试、Lint、凭据扫描和构建 | 实验性支持 |
| Windows | 锁文件安装、纯单元测试、Lint、凭据扫描和构建 | 仅编译与纯测试，不代表运行支持 |

候选工作流位于 `.github/workflows/ci.yml`。它只授予仓库内容读取权限，不安装服务、不修改系统启动项、不操作 Gateway，也不上传日志、测试 HOME、浏览器 profile、配置、凭据或会话。工作流固定使用官方 `actions/checkout` `v4.3.1`（`34e114876b0b11c390a56381ad16ebd13914f8d5`）和 `actions/setup-node` `v4.4.0`（`49933ea5288caeca8642d1e84afbd3f7d6820020`）快照，且 checkout 不持久化 GitHub 凭据。

`scripts/ci-foundation.test.mjs` 只验证当前候选快照的基本结构；它不是不可绕过的安全证明，工作流或环境白名单的任何修改仍须人工审查。

## 公共 CI 命令

Linux 与 macOS 使用：

```bash
npm run test:ci
```

Windows 候选只使用：

```bash
npm run test:ci:pure
```

两个命令都会创建一次性 `HOME`、`USERPROFILE`、临时目录、XDG目录和 `AI_WORKBENCH_*` 路径。完整命令还要求 `OPENCLAW_TEST_BROWSER` 指向绝对、现存、可执行且不经过符号链接的 Chrome/Chromium普通文件。所有浏览器 profile、截图、Vite缓存和构建输出均位于一次性测试根，命令结束后清理。

## 明确排除

公共 CI 不读取真实客户端目录，不需要 OpenClaw、Codex 或 Claude Code 数据，也不运行：

- `npm run test:security:real`
- `npm run test:stage3a:real`

这两项只允许维护者在明确知情的本机环境中手动执行。它们可能读取本机 Gateway状态或真实会话元数据，因此不能进入公共 CI。

## 浏览器定位

测试统一优先读取 `OPENCLAW_TEST_BROWSER`。macOS保留标准 Chrome/Chromium位置回退；Linux CI显式安装 Chromium并传入其实际可执行文件。测试不会读取正式 Chrome用户数据，只创建一次性 profile。Windows本轮不运行浏览器测试。
